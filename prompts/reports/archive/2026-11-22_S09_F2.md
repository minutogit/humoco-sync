## Implemented Safe Fixes

1. **Cluster 1 — Non-ASCII Quarter Panic Guard in Rust (`rust/src/locks.rs`)**
   - `SyncDb::get_static_lock_entry` (`rust/src/locks.rs:1378`): Added `!quarter_str.is_ascii()` before `parse_quarter(quarter_str)` so invalid multi-byte UTF-8 inputs cleanly return `Ok(None)` without slicing panic inside `humoco_proto::parse_quarter`.
   - Regression test (Fail-First verified): `locks::tests::test_s09_f2_get_static_lock_entry_non_ascii_quarter_no_panic` (`rust/src/locks.rs:1657`).

2. **Cluster 2 — PHP `9999-Q4` GC Overflow & Lock Validation/Status Parity (`php/lock_handler.php`)**
   - `lock_purge_after_secs` (`php/lock_handler.php:96-103`): Replaced `new DateTimeImmutable(sprintf('%04d-%02d-01 00:00:00', ...))` with `(new DateTimeImmutable('1970-01-01 00:00:00', new DateTimeZone('UTC')))->setDate($ny, $nm, 1)->setTime(0, 0, 0)->getTimestamp() + 30 * 86400`, handling `9999-Q4` (`$q = 39999` -> `$ny = 10000`, `253404892800`) identically to Rust `bucket_purge_after_secs`.
   - `lock_verify_receipt` (`php/lock_handler.php:413`): Changed `$ws <= 0` to `$ws < 0 || ($kb === 0 && $ws === 0)`, allowing valid `ConflictSeen` receipts at `write_seq = 0` for `known_head_receipt` cold-bucket rollback freeze (`409 bucket_self_frozen`) while preserving `FirstWrite` `write_seq >= 1`.
   - `lock_handle_batch` (`php/lock_handler.php:517`): Added `!array_is_list($rawEntries)` so associative JSON objects (`{"a": "..."}`) are rejected with `400`, matching Rust `Vec<String>`.
   - `PUT ?lock_delegate` (`php/lock_handler.php:832-848`): Ordered validation to reject malformed types, `issued_at < 0`, invalid `admin_pub`/`lock_pub` hex, and malformed/non-canonical `sig` with `400`, mismatched `admin_pub !== $adminPub` with `403`, wrong `lock_pub`/URL/`issued_at == 0` with `400`, and bad Ed25519 signature with `401` (`rust/src/locks.rs:352-384` parity).
   - Regression tests (Fail-First verified): `tests/test_php_locks.sh` Test 14 (`SYNC-S09-07`, `SYNC-S09-08`) + `locks::tests::test_s09_f2_conflict_seen_write_seq_zero_triggers_rollback_tombstone` (`rust/src/locks.rs:1671`).

## Cross-Slice / Upstream Spec Notes *(Out of `humoco-sync` Modification Scope)*

1. **`SPEC.md` §6.5 line 430 vs Rust & PHP `TICKET_POW_REPLAY_TTL_SECS` (`600s`):** `SPEC.md` §6.5 line 430 states `"120s replay table"` for ticket PoW deduplication, whereas both Rust (`TICKET_POW_REPLAY_TTL_SECS = 600`, `rust/src/locks.rs`) and PHP (`600s`, `php/lock_handler.php`) retain ticket PoW nonces for `600s` so the replay window covers the full `±300s` `pow_timestamp` tolerance (matching the invariant already enforced by `test_s01_ticket_replay_rejected_at_exact_expiry_boundary`). Code intentionally retains `600s`; `SPEC.md` prose should be aligned in a doc sync.
2. **Read-Only Upstream Note (`humoco-proto/src/retention.rs:37`):** `humoco_proto::parse_quarter` indexes `&s[4..6]` directly without an `is_ascii()` guard, causing any caller passing 7-byte multi-byte UTF-8 input to panic unless pre-guarded (left untouched in `humoco-proto` per cross-repo rule; tracked read-only).
3. **`FirstWrite` `write_seq = 0` Receipt Defense-in-Depth (`rust/src/locks.rs:804`):** `php/lock_handler.php:413` rejects `FirstWrite` receipts claiming `write_seq == 0` with `401`, whereas `rust/src/locks.rs:804` relies solely on `humoco_proto::LockReceipt::verify_signature()` (which permits any `u64` `write_seq`). Harmless in practice because honest `S.lock_sk` keys never sign a `FirstWrite` receipt with `write_seq == 0`.
