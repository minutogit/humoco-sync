## Implemented Safe Fixes

1. **Cluster 1 — Admin API & UI Input Bounds Parity (`rust/src/admin_api.rs`, `rust/src/web_routes.rs`)**
   - Removed `.clamp(1, 500)` from `api_create_codes` (`rust/src/admin_api.rs:327-338`) so out-of-range `count == 0` and `count > 500` return `400 Bad Request` directly from `SyncDb::create_redeem_codes`.
   - Rejected `duration_days == Some(0)` in `api_set_user_profile` (`187-189`) and `api_create_codes` (`320-322`), and `expires_in_days == Some(0)` in `api_create_codes` (`323-325`) with `400 Bad Request`.
   - Updated `admin_create_code_submit` (`rust/src/web_routes.rs:1521-1525`) to reject `count > 100` (and `0`) with `/admin?err=Code+count+must+be+between+1+and+100` instead of silently clamping to `100`.
   - Regression test: `test_s05_recheck_admin_api_bounds_and_ui_session_hardening` (`rust/tests/integration_tests.rs:7379-7552`).

2. **Cluster 2 — Admin Session Cookie, Logout CSRF & `no-store` Redirect Hygiene (`rust/src/web_routes.rs`)**
   - Added `is_https_url` (`rust/src/web_routes.rs:1561-1565`) for case-insensitive `"https://"` detection across `admin_login_submit` (`1359`) and `admin_logout_submit` (`1389`).
   - Updated `admin_logout_submit` (`1385-1387`) to fail closed before emitting `Set-Cookie: ...; Max-Age=0` when `verify_admin_cookie_and_csrf` fails, blocking unauthenticated Logout CSRF.
   - Added `admin_redirect` (`1567-1572`) attaching `Cache-Control: no-store` to all `/admin/*` `303` redirects (`admin_login_submit`, `admin_logout_submit`, `admin_user_profile_submit`, `admin_user_status_submit`, `admin_user_delete_submit`, `admin_create_code_submit`).
   - Regression tests: `test_s05_recheck_admin_api_bounds_and_ui_session_hardening` (`rust/tests/integration_tests.rs`) & `web_routes::tests::test_s05_recheck_uppercase_https_cookie_secure_and_logout_csrf` (`rust/src/web_routes.rs:1733-1825`).
