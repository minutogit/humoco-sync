## Deferred Uncertainties / Design Questions

- **`SYNC-S08-07` — Broken Docker Build Context for Out-of-Tree `humoco-proto` (`Dockerfile:4-7`, `docker/docker-compose.yml:3-5`, `rust/Cargo.toml:9`)**
  - **Problem:** `rust/Cargo.toml:9` declares `humoco-proto = { path = "../../humoco-proto" }`, which lies outside `docker/docker-compose.yml`'s `context: ..` (`humoco-sync/`). `Dockerfile:5-7` copies only `rust/Cargo.toml`, `rust/Cargo.lock*`, and `rust/src` and runs `cargo build --release --locked 2>/dev/null || cargo build --release`, causing every `docker build` / `docker compose build` to fail on missing `../../humoco-proto`, while `2>/dev/null || cargo build --release` suppresses `--locked` verification failures.
  - **Options:**
    1. Use Docker BuildKit `additional_contexts` (`humoco-proto: ../../humoco-proto` in `docker-compose.yml` + `COPY --from=humoco-proto . /humoco-proto` in `Dockerfile`) and drop the un-locked fallback (`RUN cargo build --release --locked`).
    2. Set `docker-compose.yml` `context: ../..` (workspace root `humoco/`) with adjusted `COPY` paths in `Dockerfile` and a workspace-level `.dockerignore`.
    3. Vendor or reference `humoco-proto` via crate registry / pinned git dependency so `humoco-sync/` builds standalone without external sibling paths.
  - **Recommendation:** **Option 1** (BuildKit `additional_contexts` + strict `--locked`, preserving standalone `humoco-sync/` root context) or **Option 3** once `humoco-proto` is published/pinned. Left untouched awaiting maintainer packaging preference.
