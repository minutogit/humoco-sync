## Implemented Safe Fixes

### Cluster 1 — Rate Limiter State Persistence, Lockout Expiry & Locked Auth Enforcement
- **`SYNC-S06-01`** (`php/sync.php:398-455, 522-524, 563-605, 905-971`)
  - **Root Cause:**
    1. On a fresh installation where `.state.php` did not yet exist, `GET ?info` and `HEAD` generated `$state['pepper']` in memory without persisting `.state.php`, causing the HMAC pepper for `ratelimit.bin.php` to rotate on every request until the first mutating write.
    2. `$bucket['lastTs'] = $now` was overwritten unconditionally before `ip_is_locked($bucket, $now)`, locking out an offending IP indefinitely across retries because `$now - $bucket['lastTs']` stayed `0 < 900`, and `failCount >= 10` was never cleared after `elapsed >= 900` seconds.
    3. Invalid-auth `PUT`/`DELETE`/admin endpoints incremented `failCount` without first rejecting already-locked IPs with `429 Retry-After: 900`.
  - **Fix:**
    - Track `$stateNeedsSave` whenever `.state.php` is missing/corrupt/repaired and persist `.state.php` immediately (`php/sync.php:398-455, 522-524`).
    - Compute `$elapsed` before updating `lastTs`; reset `failCount` to `0` once `failCount >= 10 && $elapsed >= 900`; preserve `lastTs` while locked (`failCount >= 10`) (`php/sync.php:563-570`).
    - Added `sync_fail_ip_and_respond()` (`php/sync.php:592-605`) to return `429 Retry-After: 900` on invalid/unauthorized authentication attempts from locked IPs while preserving CGNAT valid-Ed25519 request execution.
  - **Fail-First Regression Test:** `tests/run.sh` (`run_php_s06_security_regression_tests`, `SYNC-S06-01` assertions covering fresh `GET ?info` burst `429`, 10-fail IP lockout -> `429` on invalid signature `PUT`, `200` CGNAT bypass on valid signature `PUT`, and clean `900s` lockout expiry).

### Cluster 2 — Atomic Disk Writes (`fsync`), Nonce Persistence Across Error Paths & Non-Destructive Quota/Key Checks
- **`SYNC-S06-02`** (`php/sync.php:88-106, 134, 489-495, 663, 1157, 1357, 1641, 1722`)
  - **Root Cause:** File writes used `file_put_contents()` on predictable `mt_rand()` temp paths without `O_EXCL` (`'xb'`), exact byte-count validation, `fflush()`, `fsync()`, `json_encode` error checks, or orphan temp cleanup on rename failure.
  - **Fix:** Introduced `sync_atomic_write(string $path, string $bytes): bool` (`php/sync.php:88-106`) using CSPRNG `.tmp.<basename>.<pid>.<hex>` created exclusively with `fopen($tmp, 'xb')`, exact `fwrite() === strlen($bytes)` verification, `fflush()`, `fsync()`, atomic `rename()`, and `@unlink($tmp)` cleanup on error. Applied across `data/.htaccess`, `save_state()`, `rebuild_index()`, `members.<channel>.php`, `revocation.json`, `.media.bin`, and slot `.bin` writes.
- **`SYNC-S06-03`** (`php/sync.php:497-520, 723-843, 1138-1214, 1250-1365, 1400-1440, 1544-1754, 1896-1997`)
  - **Root Cause:**
    1. Post-signature errors (`400`/`403`/`409`/`412`/`507`) and empty `DELETE`s returned without calling `save_state()`, discarding consumed nonces (enabling replay of failed signed requests within the timestamp window) and discarding `member_buckets` / `lazy_prune_slots()` updates.
    2. `evict_oldest_media_for_space()` and `ensure_user_quota_with_media_eviction()` unlinked older `media` blobs iteratively before verifying whether the new upload could fit after all media evictions, destroying existing media on a failing `507` upload.
    3. Standard slot `PUT` loaded/initialized `.lock_key.php` via `lock_load_or_init_keys($dataDir)` *after* evicting media and writing the slot file, risking uncaught `LockAbort` `500` after mutating storage without returning `slot_ack`.
  - **Fix:**
    - Added `sync_save_and_respond()` and `sync_check_member_ratelimit()` (`php/sync.php:497-520`) and routed all post-nonce and post-state-mutation exits through `sync_save_and_respond()`.
    - Refactored `evict_oldest_media_for_space()` (`php/sync.php:723-770`), `ensure_user_quota_with_media_eviction()` (`php/sync.php:773-843`), `PUT media` (`php/sync.php:1576-1605`), and `PUT` standard slot (`php/sync.php:1694-1720`) to pre-compute non-evictable storage and return `507` before unlinking any media when impossible to satisfy.
    - Moved `lock_load_or_init_keys($dataDir)` inside `try / catch (LockAbort)` *before* media eviction and atomic slot commit in `PUT` (`php/sync.php:1685-1689`).
  - **Fail-First Regression Test:** `tests/run.sh` (`run_php_s06_security_regression_tests`, `SYNC-S06-03` assertions verifying `409` replay after `400 ?admin_config`, `412 PUT`, and empty `DELETE`; `507` preservation of `mem1` media blob; and anti-amnesia `LockAbort` `500` leaving slot unwritten on disk).

### Cluster 3 — Sync Protocol & Input/Validation Parity with Rust & `SPEC.md`
- **`SYNC-S06-04`** (`php/sync.php:230-281, 1001-1061, 1142-1202, 1560-1567, 1682, 1967-1974`)
  - **Root Cause:**
    1. `PUT media` bypassed `If-Match` / `If-None-Match` conditional precondition enforcement.
    2. `HEAD` ignored `media.ttl_days` expiry and missing `.media.bin` files when computing `X-Media-Count`, `X-Media-Bytes`, `X-Slot-Occupied`, and `ETag`.
    3. `PUT ?members&channel=card` pruned media blobs without consulting `load_channel_members($configFile, 'media')` (deleting uploads belonging to explicit `media` channel members), validated `$maxMembers` before pubkey format validation/deduplication, and used `/^[0-9a-f]{64}$/` (matching trailing `\n`).
    4. Standard-slot `DELETE` checked `if (!$isMember && !$slotExists)` (`404`) before `verify_ed25519_detached()` (`401`), acting as a pre-auth membership/slot existence oracle.
  - **Fix:**
    - Extracted shared `sync_normalize_etag_token()` and `sync_check_put_preconditions()` (`php/sync.php:230-281`, supporting `If-None-Match` comma lists, `*`, and weak `W/` tags) and enforced it on both `PUT media` (`php/sync.php:1567`) and `PUT` standard slots (`php/sync.php:1682`).
    - Updated `HEAD` media inspection to check file existence and `media.ttl_days` expiration (`php/sync.php:1001-1061`).
    - Updated `PUT ?members` to validate `\A[0-9a-f]{64}\z` per entry, deduplicate before checking `$maxMembers`, and compute effective `media` membership via `load_channel_members($configFile, 'media')` (`php/sync.php:1142-1202`).
    - Moved Ed25519 signature verification (`php/sync.php:1967-1970`) ahead of `if (!$isMember && !$slotExists)` (`php/sync.php:1972-1974`) in `DELETE`.
- **`SYNC-S06-05`** (`php/sync.php:16-21, 178-228, 283-299, 420-429, 905, 943, 1100, 1220, 1272-1350, 1370, 1446, 1487, 1498-1500, 1759, 1836`)
  - **Root Cause:**
    1. Missing startup guard for `ext-sodium` / `sha3-256`; uncaught `SodiumException` possible if libsodium rejects key/sig input.
    2. `$state['admin_pubkey']` was only initialized once when missing/invalid and ignored subsequent `config.php` `admin_pubkey` updates.
    3. Unbounded `file_get_contents('php://input')` on admin `PUT ?members` / `?revoke` / `?admin_config` risked memory exhaustion (`memory_limit`).
    4. `PUT ?revoke` allowed `is_numeric` floats/scientific notation, trimmed signed `reason`, lacked strict `is_string`/`[\x00-\x1f\x7f]` control-char checks, lacked URL `2048`-byte cap/HTTPS host validation, and accepted `http://localhost.evil.com` via prefix match (matching `SYNC-S01-06`).
    5. Timestamps used permissive `is_numeric` with `/^...$/` regexes; extra query parameters on routes fell through silently instead of `405`; `X-Media-Id` was accepted and ignored on non-media `PUT`.
  - **Fix:**
    - Added startup check for `sodium_crypto_sign_verify_detached` and `sha3-256` (`php/sync.php:16-21`) and `try / catch (\Throwable)` in `verify_ed25519_detached()` (`php/sync.php:190-194`).
    - Synchronized `$state['admin_pubkey']` when `config.php` provides a valid 64-hex `admin_pubkey` (`php/sync.php:420-429`).
    - Added bounded streaming reader `sync_read_bounded_body()` (`php/sync.php:201-228`) enforced on `PUT ?members` (`8 MiB`), `PUT ?revoke` (`64 KiB`), `PUT ?admin_config` (`16 KiB`), and `PUT` uploads.
    - Tightened `contains_control_chars()`, `is_sync_url_valid()` (`<= 2048` bytes, no ASCII control/space chars, HTTPS host non-empty, strict loopback regex), and `PUT ?revoke` field validation (`is_int`, strict hex/string checks, un-trimmed `reason`) (`php/sync.php:283-299, 1272-1350`).
    - Added `sync_is_int_timestamp()` (`\A-?[0-9]{1,19}\z`), `\A...\z` anchors, strict `$_GET` route guards, and `X-Media-Id` rejection on non-media `PUT` (`php/sync.php:197-199, 905, 943, 1100, 1220, 1370, 1446, 1487, 1498-1500, 1759, 1836`).
  - **Fail-First Regression Test:** `tests/run.sh` (`run_php_s06_security_regression_tests`, `SYNC-S06-04` and `SYNC-S06-05` assertions).

### Cluster 4 — Apache `.htaccess` Dotfile Blocking & Data Directory Traversal Defense
- **`SYNC-S06-06`** (`php/.htaccess:5`, `php/sync.php:57-71`)
  - **Root Cause:** `php/.htaccess` enumerated only `.state.php` and `.lock` inside `<FilesMatch>`, leaving arbitrary dotfiles (such as `.htaccess` or `.lock_key.php` if `data_dir` were misconfigured or placed under web root) unprotected compared to `<data_dir>/.htaccess`. Additionally, `$dataDirSetting` only checked `strpos(..., '..') !== false`, allowing `''`, `'.'`, `"\0"`, `'anchors'`, and `'sync'`.
  - **Fix:**
    - Expanded `php/.htaccess:5` `<FilesMatch>` to `^(\..*|config\.php|lock_handler\.php|lock_rotation\.php|ratelimit\.bin\.php|members\..*\.php|.*\.tmp.*)$`.
    - Hardened `$dataDirSetting` validation in `php/sync.php:57-71` to require `is_string()` and reject empty strings, `"\0"`, `'..'`, `'.'`, `'anchors'`, and `'sync'`.
  - **Fail-First Regression Test:** `tests/run.sh` (`run_php_s06_security_regression_tests`, `SYNC-S06-06` assertions checking regex match on `.lock_key.php`/`.htaccess` and HTTP `500` on `data_dir = '.'`).

## Deferred Uncertainties / Design Questions

- **`SYNC-S06-07` (`php/sync.php:1576-1638` vs `rust/src/db.rs:1089-1184`):**
  - **Problem:** When `PUT media` encounters full `max_user_count`, `media.max_user_bytes`, `media.max_channel_mb`, or `max_total_storage_mb`, `php/sync.php` returns `507 Insufficient Storage` immediately (only invoking `ensure_user_quota_with_media_eviction` against the member's total account budget `max_user_storage_mb`), whereas `rust/src/db.rs:1089-1184` LRU-evicts older `media` blobs on new `PUT media` uploads to make room for all four budgets.
  - **Options:**
    1. Keep current PHP `507` behavior on `PUT media` per `SPEC.md` §3 (which defines Priority-3 `media` LRU eviction for Priority-1/2 channel uploads when capacity is tight).
    2. Implement LRU eviction of older `media` blobs on new `PUT media` uploads in `php/sync.php` for full behavioral parity with `rust/src/db.rs:1089-1184`.
    3. Clarify whether Priority-3-evicts-Priority-3 on `PUT media` is intended or if `rust/src/db.rs` should also reject `507` on `PUT media` channel/count caps.
  - **Recommendation:** Option 1 (keep `SPEC.md` §3 behavior in PHP) or Option 2 + `SPEC.md` §3 clarification if identical PHP/Rust `PUT media` eviction is preferred.
