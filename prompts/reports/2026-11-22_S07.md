## 3. Implemented Safe Fixes

### Cluster 1 — `SYNC-S07-08`: Universal `max_buckets` Cap with Self-Freeze Tombstone Exemption
- **Root Cause:** Following `f47afd8`, only `lock_bootstrap_anchor()` checked `max_buckets`. Creating new buckets via `POST ?lock_ticket`, `POST ?lock`, `POST ?lock_import`, or `POST ?lock_commit` (`finalize`) bypassed `$cfg['max_buckets']`. Meanwhile, Rust commit `3fb389` / `5d0d1de` intentionally kept `known_head_receipt` rollback tombstones exempt so an attacker exhausting `max_buckets` cannot suppress rollback `409 bucket_self_frozen` evidence.
- **Fix:**
  - Added shared helper `lock_bucket_count(array $p): int` in `php/lock_handler.php:158-160` and reused it in `php/lock_rotation.php:355`.
  - Enforced `lock_bucket_count($p) >= $cfg['max_buckets']` (`507`) for unseen buckets in `lock_handle_ticket()` (`php/lock_handler.php:496`) and normal `GenesisTicket` creation in `lock_handle_batch()` (`php/lock_handler.php:563`), keeping the `known_head_receipt` Self-Freeze tombstone branch exempt.
  - Enforced `max_buckets` when `$oldB === null` in `lock_handle_import()` (`php/lock_rotation.php:668`) and when `$existingB === null` in `lock_handle_commit()` (`finalize`) (`php/lock_rotation.php:789`, passing `$cfg` into the lock closure and failing before mutating `$rFile` or `anchors/$aHex.bin`).
- **Fail-First Proof & Verification:** Added Test 10 in `tests/test_php_locks.sh:769-961`; observed fail-first `200` on unseen buckets (`fin_rot_leak:1`, `fin_anc_leak:1`), then verified all 11 assertions in Test 10 pass (`507` on unseen buckets, `200` on existing buckets, `409 bucket_self_frozen` tombstone exemption, `0` leaked metadata/anchor files).

### Cluster 2 — `SYNC-S07-09`: Monotonic `(write_seq, bucket_head)` Preservation in `lock_handle_import()`
- **Root Cause:** `lock_handle_import()` recomputed `$ws = 0` and `$bh = HUMOCO_BUCKET_INIT_V1` over `slotsResolved` in lexicographical `ksort` slot order (`SORT_STRING`). Whenever slots had been committed out of lexicographical slot order prior to rotation, or an older server caught up on missing slots from peer snapshots, post-rotation `(write_seq, bucket_head)` regressed or diverged, causing legitimate pre-rotation `known_head_receipt` presentations to fail falsely with `409 bucket_self_frozen`.
- **Fix:** Updated `lock_handle_import()` (`php/lock_rotation.php:674-716`) to snapshot existing slot `entryHash` values (`$prevSingleHashes`) from `$oldB['slots']` before modifying slot files, seed `($ws, $bh)` from `$oldB` when non-null (failing `500` if stored head metadata is corrupt), advance `($ws, $bh)` only for newly imported or hash-changed `single` entries, persist all new `.lock` files via `lock_atomic_write()`, and prune superseded `.lock` files only after JSON updates succeed.
- **Fail-First Proof & Verification:** Added Test 11 in `tests/test_php_locks.sh:963-1120`; observed fail-first `409 bucket_self_frozen` on post-rotation `known_head_receipt` (`after_code:409, catchup_code:409`), then verified all 4 assertions pass (`200`, monotonic `write_seq` `2 -> 3` and `3 -> 4`).

### Cluster 3 — `SYNC-S07-10`: Full `migration_chain` Prefix Verification on `lock_import` & `finalize`
- **Root Cause:** Neither `lock_handle_import()` nor `lock_handle_commit()` (`finalize`) checked full `migration_chain` prefix agreement (`0..count($exChain)-1`) against `$existingR['active_manifest']` (parity with Rust `5d0d1de` `manifests_share_chain_prefix` in `rust/src/lock_rotation.rs:127-141`). `lock_handle_import()` accepted `to_rev > rev` proposals anchored on conflicting earlier certificates, `finalize` accepted higher revisions (`rev > $exRev`) with conflicting earlier certificates, and `finalize` at equal revision (`rev === $exRev`) only checked the latest certificate (`$exLatest`), accepting conflicting earlier `cert[0]` prefixes when the final transition certificate happened to match.
- **Fix:** Added `lock_manifests_share_chain_prefix(array $existing, array $incoming): bool` (`php/lock_rotation.php:319-335`) comparing core proposal digests (`lock_proposal_digest`) and `imported_state_hash` across all indices of `$existing['migration_chain']`; called it in `lock_handle_import()` (`php/lock_rotation.php:661`) when `$existingR !== null` and in `lock_handle_commit()` (`finalize`) (`php/lock_rotation.php:775`) before handling `revision === $exRev` idempotency.
- **Fail-First Proof & Verification:** Added Test 12 in `tests/test_php_locks.sh:1122-1282`; observed fail-first `200` on all three fork scenarios (`imp_fork:200`, `fin_higher_fork:200`, `fin_eq_tail_fork:200`), then verified all 4 assertions pass (`409` on all three forks, `200` on valid linear continuation `m2A -> m3A`).

### Cluster 4 — `SYNC-S07-11`: IPv4-Mapped IPv6 & IPv6 `/64` Rate-Limit Normalization
- **Root Cause:** `lock_ip_ratelimit_allow()` hashed the raw `$_SERVER['REMOTE_ADDR']` string (`php/lock_handler.php:234`), allowing dual-stack IPv4-mapped clients (`::ffff:a.b.c.d` vs `a.b.c.d`) and SLAAC/routed IPv6 clients within the same `/64` prefix to bypass the per-IP token bucket (`60` burst, `2/s` refill), diverging from `php/sync.php:sync_rate_limit_ip_key` and `rust/src/ratelimit.rs`.
- **Fix:** Added standalone `lock_rate_limit_ip_key(string $rawIp): string` (`php/lock_handler.php:208-222`) normalizing IPv4-mapped IPv6 (`::ffff:...`) to IPv4, preserving `::1` loopback isolation, and masking all other IPv6 addresses to `/64`; applied it inside `lock_ip_ratelimit_allow()` (`php/lock_handler.php:234`).
- **Fail-First Proof & Verification:** Added Test 13 in `tests/test_php_locks.sh:1284-1349`; observed fail-first bypass (`same64_allow:true`, `mapped_v4_allow:true`, `loop_alias_allow:true`), then verified all 5 assertions pass (`2001:db8:abcd:0001::1..3c` within `/64` throttles `2001:db8:abcd:0001:ffff::99` while leaving `2001:db8:abcd:0002::1` unthrottled; `::ffff:198.51.100.7` shares bucket with `198.51.100.7`; canonicalized `::1` stays isolated from `::2`).
